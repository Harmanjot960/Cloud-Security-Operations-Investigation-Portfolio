## 1. Summary

A custom Microsoft Sentinel detection rule identified a live, externally originating brute-force attack against a self-hosted Windows Server 2022 virtual machine with internet-exposed RDP.

Three external source IP addresses generated a combined **174 failed authentication attempts** against the same targeted username during an approximately 21-minute observed activity window.

Unlike the simulated Sentinel Training Lab investigations in this portfolio, this investigation used **live Windows Security telemetry generated by real internet traffic** against infrastructure operated for this exercise.

The investigation followed this SOC workflow:

**Live Windows telemetry → Custom KQL detection → Sentinel incident → Alert triage → Authentication analysis → MITRE ATT&CK mapping → Incident classification and resolution**

## 4. Detection Query

The final detection rule queried the `Event` table populated by the live Windows Security log collection pipeline:

```kql
Event
| where EventLog == "Security" and EventID == 4625
| where Computer == "WindowsVM"
| extend SourceIP = extract(@"Source Network Address:\s*([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+)", 1, RenderedDescription)
| where isnotempty(SourceIP)
| summarize FailedAttempts = count(), Timestamp = max(TimeGenerated) by SourceIP, Computer
| where FailedAttempts > 20
| project Timestamp, SourceIP, Computer, FailedAttempts
```

### Detection Logic

The query:

1. Filters for Windows Security events.
2. Restricts the dataset to Event ID 4625.
3. Limits detection to `WindowsVM`.
4. Extracts the IPv4 source address from `RenderedDescription`.
5. Removes events without a source IP.
6. Counts failed authentication attempts by source IP and host.
7. Identifies sources exceeding 20 failures.
8. Returns the timestamp, source IP, host, and attempt count.

The detection focuses on **external source-IP behavior** rather than simply counting all failed logons on the host.

| `91.238.181.92`  |              74 | Sustained automated authentication attempts |

| `45.227.254.151` |              26 | Shorter automated burst                     |
| **Total**        |         **174** | **Multiple-source brute-force activity**    |

All three sources targeted the same host and username during an approximately 21-minute period.

The repeated failures, common target, external source addresses, and attempt volumes are consistent with automated internet scanning and credential-guessing activity.

The evidence does **not** establish that the three IP addresses belonged to the same threat actor. Their activity is more consistent with independent scanners or automated sources discovering the same exposed RDP service.

## 7. Authentication Analysis

### 7.1 Targeted Username

The targeted username was:

```text
Administrator
```

No local account named `Administrator` existed on the monitored VM.

Therefore, the observed authentication attempts targeted a **non-existent account**, meaning those attempts could not successfully authenticate to that specific account.

### 7.2 Authentication Package and Logon Type

The observed authentication package was:

```text
NTLM
```

The observed logon type was:

```text
3 - Network
```

This is consistent with network-based authentication activity against the exposed service.

### 7.3 Failure Codes

Observed failure codes included:

```text
0xC000006D
0xC0000064
```

These failure codes are consistent with authentication failures involving an invalid username and/or invalid credentials.

### 7.4 Successful Authentication

No successful authentication was identified from the observed source IP addresses.

The available evidence supports **failed credential-guessing activity without evidence of successful account compromise**.

## 8. Attack Assessment

The activity is assessed as a **live external RDP brute-force attack** based on:

* Publicly exposed RDP service.
* Three external source IP addresses targeting the same Windows host.
* Repeated Event ID 4625 failures.
* 174 combined failed authentication attempts.
* Approximately 21-minute activity window.
* Repeated targeting of the same username.
* NTLM network authentication.
* Failure codes consistent with invalid or unknown credentials.
* No successful authentication identified.

The evidence does not establish successful compromise of the Windows VM or that the three source IP addresses were controlled by a single threat actor.

## 11. Detection Engineering

An important part of the investigation was validating the correct Log Analytics table for the live Windows Security telemetry.

An initial detection approach used the `SecurityEvent` table associated with the Sentinel Training Lab's simulated Windows security dataset.

The live Windows VM telemetry collected through Azure Monitor Agent was instead observed in the `Event` table with:

```kql
EventLog == "Security"
```

The detection was therefore updated to query the `Event` table.

The final detection also restricted activity to `WindowsVM`, extracted the source IP from `RenderedDescription`, grouped failures by source IP and computer, and triggered when the count exceeded 20.

This demonstrated the importance of validating detection logic against the **actual ingestion path and schema** rather than assuming that similarly named Windows event data will populate the same table.

The corrected detection successfully identified the live RDP brute-force activity.

## 16. Recommendations

* Restrict inbound RDP access on TCP/3389 to trusted administrative IP ranges.
* Remove public RDP exposure where possible.
* Use a VPN, Azure Bastion, or another controlled administrative access mechanism instead of exposing RDP directly to the internet.
* Monitor for Event ID 4624 following brute-force activity to identify successful authentication.
* Review authentication activity associated with the targeted host and username.
* Apply appropriate account lockout and authentication-hardening policies.
* Review NSG rules periodically to ensure administrative services are not unintentionally exposed.
* Use Network Level Authentication and stronger administrative access controls where appropriate.

## 19. Conclusion

The investigation confirmed a **live external RDP brute-force attack** against the self-hosted `WindowsVM`.

The custom Microsoft Sentinel detection identified Event ID 4625 failures and surfaced three external source IP addresses responsible for **174 failed authentication attempts within approximately 21 minutes**.

The activity targeted the same host and username, used NTLM network authentication, and generated failure codes consistent with invalid or unknown credentials. No successful authentication was identified.

The investigation demonstrated an end-to-end SOC detection and triage workflow:

**Windows Server → Azure Monitor Agent → Data Collection Rule → Log Analytics → Microsoft Sentinel → Custom KQL Detection → Incident Generation → Alert Investigation → Evidence Analysis → MITRE ATT&CK Mapping → Classification and Resolution**

Unlike the simulated Sentinel Training Lab investigations in this portfolio, the evidence in this investigation originated from **real internet traffic against live infrastructure**.
